HMatrices.AbstractCompressor — Type
abstract type AbstractCompressor

Types used to compress matrices. A compressor comp is called as comp(K, irange, jrange, buf) and returns an RkMatrix approximating K[irange, jrange], where buf is a workspace created by allocate_buffer(comp, T) (nothing by default). During the assembly of an HMatrix, it is called with the index ranges of each admissible block.

source
HMatrices.AbstractKernelMatrix — Type
abstract type AbstractKernelMatrix{T} <: AbstractMatrix{T}

Interface for abstract matrices represented through a kernel function f, target elements X, and source elements Y. The matrix entry i,j is given by f(X[i],Y[j]). Concrete subtypes should implement Base.size, Base.getindex(K, i::Int, j::Int), and rowelements and colelements, whose elements have a center used to cluster them.

Implementing getblock! (e.g. with SIMD vectorization) can improve the speed of assembling an HMatrix.

HMatrices.AbstractSplitter — Type
abstract type AbstractSplitter

An AbstractSplitter is used to split a ClusterTree. The interface requires the following methods:

  • should_split(clt,depth,splitter) : return a Bool determining if the ClusterTree should be further divided
  • split!(clt,splitter) : perform the splitting of the ClusterTree handling the necessary data sorting.

See GeometricSplitter for an example of an implementation.

Tree structure used to cluster points of type SVector{N,T} into HyperRectangles.

HMatrices.KernelMatrix — Type
KernelMatrix{Tf,Tx,Ty,T} <:: AbstractKernelMatrix{T}

Generic kernel matrix representing a kernel function acting on two sets of elements. If K is a KernelMatrix, then K[i,j] = f(X[i],Y[j]) where f::Tf=kernel(K), X::Tx=rowelements(K) and Y::Ty=colelements(K).

Examples

X = rand(SVector{2,Float64},2)
Y = rand(SVector{2,Float64},2)
K = KernelMatrix(X,Y) do x,y
    sum(x+y)
end

HMatrices.PartialACA — Type
struct PartialACA

Adaptive cross approximation algorithm with partial pivoting. This structure can be used to generate an RkMatrix from a matrix-like object M as follows:

using LinearAlgebra
using HMatrices: PartialACA
rtol = 1e-6
comp = PartialACA(;rtol)
A = rand(10,2)
B = rand(10,2)
M = A*adjoint(B) # a low-rank matrix
R = comp(M, axes(M)...) # compress the entire matrix `M`
norm(Matrix(R) - M) < rtol*norm(M) # true

# output

true

Because it uses partial pivoting, the linear operator does not have to be evaluated at every i,j. This is usually much faster than TSVD, but due to the pivoting strategy the algorithm may fail in special cases, even when the underlying linear operator is of low rank.

ACA estimates its error from the last cross only, which can stop it too early, or miss part of a block whose rows visited by ACA vanish on it (e.g. a double layer between two parallel sheets). Before stopping, it checks the residual at max(samples*k, 20) entries, where k is the current rank: half at pseudo-random positions, half in the rows and columns of the smallest norms in the factors, which the approximation leaves out; it continues from the largest residual if they show an error above the tolerance. samples = 0 disables this check, which is also skipped when an entry costs a whole column (in the products of the factorizations).

With recompress = true (the default), the result is recompressed by a truncated SVD, computed from QR factorizations of its factors (see TSVD), with the same tolerances, which lowers its rank at the cost of a QR factorization of each factor and an SVD of a small matrix. In the factorizations, the lower ranks also make the later products cheaper.

The default rtol is sqrt(eps(R)), where R is the real type underlying the entries of the compressed matrix, or only the accuracy attainable with R if atol or rank is given. An rtol smaller than that accuracy (10eps(R)) is raised to it, or throws an ArgumentError if it is positive, so the rank of a block can stay below rank when the rest of the block is at the level of rounding errors.

HMatrices.RandomizedSVD — Type
RandomizedSVD(; atol = 0, rank = typemax(Int), rtol = nothing, block = 4)

Compression algorithm based on a randomized SVD (Halko, Martinsson and Tropp, "Finding structure with randomness", SIAM Review 53, 2011): an orthonormal basis Q of the range of the block M is given by the Householder QR factorization of the products of M with random Gaussian vectors, extended by blocks of block vectors until the error `|M

  • QQ'M|estimated from the last block is belowmax(atol, rtol*|M|)`, in the

Frobenius norm. The SVD of Q'*M is then truncated as by TSVD, and at most rank singular values are kept; with a rank, the basis has one more block than the rank, so that the singular values kept are accurate. The default rtol is the same as for PartialACA.

It only uses the products M*X and M'*X, whose evaluations are batched. It suits the blocks whose updates are deferred in the factorizations and the products: their products are cheap, while each of their entries costs a whole column. It is the default compressor of lu and cholesky. Any other block is first evaluated entirely, so PartialACA should be preferred for the assembly.

The error is estimated from the residuals of a single block of random vectors, which is more reliable for larger blocks. The random vectors only depend on the size of the block, so that the results are reproducible.

HMatrices.TSVD — Type
struct TSVD

Compression algorithm based on a posteriori truncation of an SVD: the singular values σᵣ₊₁, σᵣ₊₂, … are dropped, for the smallest r such that the error of the truncation in the Frobenius norm, sqrt(σᵣ₊₁² + σᵣ₊₂² + ⋯), is at most max(atol, rtol*|M|), where |M| is the Frobenius norm of the matrix (the norm in which PartialACA estimates its error), and at most rank are kept. This is the best approximation of its rank. It evaluates every entry of the block, so it should be used mostly for "small" matrices. The default rtol is the same as for PartialACA.

HMatrices.ThreadsExecutor — Type
ThreadsExecutor(; check_accesses = false)

Executor running pieces of work as tasks on Julia's threads, each one waiting only for the last piece of work which wrote each of the objects it reads or writes: with executor = ThreadsExecutor(), the algorithms which take an executor (e.g. lu!, cholesky!) run in parallel, as with threads = true. An error raised by a piece of work is rethrown as is, without the backtrace of its task; running sequentially (see SerialExecutor) gives the full backtrace.

spawn!(work, ex, reads, writes) registers work(), which reads the objects of reads and modifies those of writes, and wait(ex) returns once all the work spawned is done, then forgets it, and rethrows the first error of a piece of work.

There is no general dependency analysis: the executor only keeps the last writer of every object, which is enough for drivers satisfying the following access pattern:

  • an object is written by a sequence of pieces of work, which are run in the order in which they are spawned;
  • an object is only read once final, i.e. after its last write has been spawned, so that there are no write-after-read hazards.

The objects written are leaves of an HMatrix, or other objects (e.g. a low-rank term computed by one piece of work and read by others). A read of an internal block of an HMatrix is a read of all its leaves: it waits for a join over the last writers of its leaves, created at its first read and reused afterwards. With check_accesses = true, the executor checks this access pattern: that no object is written after it, or an internal block containing it, was read.

A piece of work never blocks: it counts its unfinished dependencies, and is spawned as a task by the piece of work completing the last of them. The objects are identified by their objectid, so that the executor does not keep them alive.

HMatrices.assemble_hmatrix — Function
assemble_hmatrix(K, X, Y = X; atol = 0, rtol, rank, eta = 3, nmax = 50, threads = true)

Approximate the matrix K by an HMatrix, where X and Y are the points (SVectors, or elements with a center) associated with the rows and the columns of K. The points are only used to cluster the indices, and are not modified.

  • K can be any AbstractMatrix (e.g. a KernelMatrix), with scalar or SMatrix entries; getblock! can be overloaded to compute its blocks faster. If K is a Hermitian, only its upper triangle is assembled and a Hermitian HMatrix is returned (this requires Y === X).
  • atol, rtol and rank control the compression of the low-rank blocks, by a partial ACA followed by a recompression (see PartialACA); by default rtol = sqrt(eps) of the real type of the entries, or only the accuracy attainable with that type if atol or rank is given.
  • Two clusters are compressed if min(diameters) < eta * distance; eta = Inf compresses every pair of disjoint clusters (weak admissibility).
  • nmax is the maximum number of points in a leaf of the cluster trees.
  • The leaves are assembled in parallel with threads = true (when Julia runs on several threads).

Every operation on the result (products, Matrix, factorizations) uses the ordering of X and Y.

HMatrices.getblock! — Method
getblock!(block,K,irange,jrange)

Fill block with K[i,j] for i ∈ irange, j ∈ jrange, where block is of size length(irange) × length(jrange).

A default implementation exists which relies on getindex(K,i,j), but this method can be overloaded for better performance if e.g. a vectorized way of computing a block is available. The indices are in the ordering of K, and irange/jrange can be any vectors of integers, not only ranges.

HMatrices.rowperm — Method
rowperm(H)

The permutation of the rows of the whole matrix into the ordering in which it is stored: for the root H of an HMatrix, the stored row i is the row rowperm(H)[i] of the matrix approximated by H. For a block of H, it is the permutation of the whole matrix (the rows of the block are rowperm(H)[rowrange(H)]).

The returned vector belongs to the cluster tree and must not be modified.

LinearAlgebra.cholesky! — Method
cholesky!(M::HermitianHMatrix, compressor; threads = true, executor)

Hierarchical Cholesky factorization M = U'U in place, the factor being stored in the upper triangle of M, which must hold the data of M (as for the Hermitian assembled by assemble_hmatrix); an ArgumentError is thrown otherwise. As for lu!, every update is deferred, each admissible leaf of the factor is compressed once, and the work is parallelized with threads = true or run by the given executor.

F \ b solves in the ordering of the points used to assemble M. The factors F.L and F.U are stored in the ordering of the cluster tree, with F.L * (F.U * x) ≈ Matrix(M)[F.p, F.p] * x; products and solves with them act in that ordering.

LinearAlgebra.lu! — Method
lu!(M::HMatrix, compressor; threads = true, executor)

Hierarchical LU factorization of M in place, every update being deferred: each admissible leaf of the factors is compressed exactly once, with compressor (e.g. RandomizedSVD or PartialACA), from its Schur complement. The work is parallelized with threads = true (when Julia runs on several threads), or run by the given executor (ThreadsExecutor or SerialExecutor).

F \ b solves in the ordering of the points used to assemble M. The factors F.L and F.U are stored in the ordering of the cluster trees, with F.L * (F.U * x) ≈ Matrix(M)[F.p, F.q] * x; products and solves with them act in that ordering.

The entries of M must be numbers. With threads = true, BLAS should run on a single thread (BLAS.set_num_threads(1)), since the parallelism comes from the blocks. An error raised by a threaded factorization is rethrown without the backtrace of the task which raised it; threads = false gives the full backtrace.
